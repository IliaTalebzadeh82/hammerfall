## Decisions

- `PublicAuctionSnapshot` represents only the public payload, not an event envelope or private maximum. Kafka validates envelope identity separately; Redis validates its own source/revision/write metadata and the shared payload contract. Do not infer command outcome from either derived path.
- `occurred_at` is database wall time at outbox insert. The earlier auction decision instant, transaction start, commit (not separately recorded), publisher delivery/acknowledgment and Redis projection time are distinct. Existing events cannot be relabeled accurately without historical evidence.
- `attr_readonly` is deliberately an application-code accident guard, not a privileged SQL immutability promise. Publishers may update only their retry/ack fields. The SQL type/JSON CHECK protects structural event shape without duplicating full public semantics in PostgreSQL.
- The delayed-claim test uses a one-second lease and an actual blocking PostgreSQL transaction lasting longer than that lease. The token/cursor predicates already protect stale advance/release and concurrent renewal; expired pages can still duplicate bounded maintenance work.
- Production host filtering is a safe default with explicit deployment configuration. It does not substitute for planned authentication/authorization or make the API public-ready.
- Publisher transaction ownership remains within each `run_once` row iteration. `SELECT ... FOR UPDATE SKIP LOCKED`, external enqueue/produce-and-wait, then retry or acknowledgment update all occur before commit. A process exit before delivery rolls back an unacknowledged row; exit after external acceptance but before commit can duplicate the same immutable event. A failed DB update/commit cannot falsely acknowledge. Expected dependency errors persist exponential retries; ambiguous acceptance also retries. Sidekiq acknowledgment means Redis enqueue, Kafka acknowledgment means broker acceptance. Neither changes auction truth. Same-table row locks cause temporary cross-path exclusion even though retry/ack columns are independent. The relevant ADRs now record the operational cost.
- Configuration review: publisher intervals must be finite and positive; per-cycle batch sizes are checked in 1..1000; reconciliation interval is finite and at least five seconds, with a fixed ten-minute PostgreSQL lease. Redis client network timeout is two seconds; Kafka message/socket timeouts are five/three seconds. Defaults are represented in Compose and `.env.example` after adding the two missing outbox settings. None is a strict publisher-cycle deadline. Do not multiply publisher process count without measuring PostgreSQL pool and backlog effects.
- Maintainability review of public validation, event classification, two publisher loops, Kafka audit/projection consumer setup, projection comparison, lease fencing and retry/backoff found no justified source refactor. The two publishers use explicit per-transport transaction flows; sharing a generic abstraction would obscure acknowledgment semantics and transaction ownership. Duplicate retry formula is small and currently identical. Kafka consumers duplicate setup for distinct side effects and group identity. Reconsider only on a demonstrated divergence or defect.
- No further pre-auth security repair was justified this session. Production hosts require an explicit allowlist, Cable origins have no implicit production allowance, Compose dependencies bind to loopback, and filters exclude idempotency/private fields from ordinary parameter logging. Full identity/authorization and public ingress remain later work.
- Session 2 adversarial review: acknowledgment follows confirmed external acceptance in both source paths; dependency failure cannot mark success (sabotage proved the Kafka guard). A crash or PostgreSQL acknowledgment failure rolls back the row, so retry can duplicate but not lose its immutable identity/payload. PostgreSQL row locks prevent simultaneous ownership of one row; `SKIP LOCKED` can defer the other independent path without suppressing its due predicate. No stale-owner protocol exists in this retained design. An indefinitely stalled external call can retain a transaction until process restart because no total deadline is enforced; this is an operational limitation to revisit with latency/load evidence. HMAC was not migrated, so retained replay semantics are unchanged; the weak-key dictionary risk remains explicit. No Phase 13 functionality was introduced. Final cross-system adversarial review remains for the finalization session.
