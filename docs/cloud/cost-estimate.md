# Phase 19 planning cost model

Research date: 2026-10-03. Reference region: `europe-west4` (Netherlands). **This work created no resources or cloud charges.** All figures are USD list-price planning examples, not a quote or a measured Hammerfall bill. Google's public pricing pages show Iowa by default; the worked numbers below explicitly use those **us-central1** rates because a verified Netherlands SKU export is not yet available. Before any approved apply, select `europe-west4` in the [Google Cloud Pricing Calculator](https://cloud.google.com/products/calculator), capture its dated output, add taxes/discounts/quotas and recompute every line. Do not present the Iowa subtotal as a Netherlands price.

## Assumptions and formulas

730 hours/month, on-demand, one GCP project, one cluster, two API pods, two web pods (each Node + Nginx), and seven background pods. Phase 18 requests total **1.15 vCPU and 2.0625 GiB**, but they are local guardrails. If an Autopilot cluster lacks bursting, [minimum/ratio rules](https://docs.cloud.google.com/kubernetes-engine/docs/concepts/autopilot-resource-requests) could raise these eleven pods to roughly **2.75 vCPU and 5.5 GiB**, before ephemeral storage, rollout overlap or special scheduling. This is a cost stress assumption, not a GKE observation. The exact bill depends on admitted pod requests and compute class.

**Iowa-only arithmetic sanity check:** the cost-conscious *full managed-Kafka* shape above is about `$73 + $109 + $128 + $36 + $248 = $594/month` **before** Cloud SQL disk/backups, load balancer, NAT, logs, Secret Manager, GCS, DNS, network and tax. Without a broker the illustrative subtotal is $346, but that is **not** a fully running Hammerfall deployment. A regional-HA SQL and Standard-HA Redis variant raises the same partial subtotal to about `$733/month` with the illustrative broker, before other charges. At the Google 10 MiB/s Kafka example, Kafka alone is about $1.1K/month in Iowa. These figures expose the economic weight of a managed broker and HA; they are neither a Netherlands quote nor a spend authorization.

The reference Terraform's disabled default is the only zero-cost scenario established here. A truly live portfolio deployment must either pay for a Kafka-compatible broker or undergo a separately designed/tested semantic migration. Shutting down a Kafka-dependent process or omitting the broker is not a faithful low-cost running architecture. A GKE Standard alternative needs node shape/count, bin packing and operational labor estimates before claiming savings. Discounts/free-tier credits are not guaranteed and should be modeled separately from gross costs.
